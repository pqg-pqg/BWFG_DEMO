# 百味饭馆 · 24 小时经营 Demo

- **在线预览**：https://pqg-pqg.github.io/BWFG_DEMO/ （推送到 `main` 后由 GitHub Actions 自动测试、构建并发布）
- **技术栈**：React 18 + TypeScript + Vite，测试用 Vitest。无后端，无其他运行时依赖。
- **启动命令**：`npm install` 后 `npm run dev`，浏览器打开 http://localhost:5173 。
- **实现范围**：作业文档 3–7 节的全部内容。3 级饭馆、3 级厨师、12 道菜、6 类客人；排队、落座、点单、烹饪、待出餐、结账、流失的完整循环；手动出餐和五种礼物；研发、上架、饭馆升级、厨师升级；localStorage 存档；模拟弹幕；调试用暂停和 1/2/5 倍速。
- **未实现范围**：文档第 8 节列出的所有内容；录屏、正式美术与动效；离线收益。加分项里做了“随机数可注入种子”、引擎单元测试和在线部署。
- **最复杂的状态处理**：所有计时都收敛到一个 `tick()`，见下文[时间与状态](#时间与状态)。难点是同一秒内多件事的先后顺序（菜刚做好不能立刻被扣等待时间、甜甜圈要抢在超时之前出餐、腾出的桌子要先给队首再扣排队耐心），以及炸弹、甜甜圈这类“立即生效”的礼物如何复用同一套落座和结账逻辑而不另开一条路径。
- **如果再给一天**：补一个按种子跑几千 Tick 的不变量测试（资源不为负、座位和灶眼不超额、不重复结账）；给经济数值做一轮走查，目前铭牌碎片主要靠掉落，1 升 2 级偏慢；把状态机图和模块图画出来。

## 命令

```bash
npm install        # 安装依赖
npm run dev        # 开发模式，http://localhost:5173
npm run build      # 类型检查 + 构建到 dist/
npm run preview    # 本地预览构建产物
npm test           # 运行引擎单元测试
```

需要 Node 18 及以上。地址栏加 `?seed=123` 可以固定随机种子，复现同一串客人和抽奖结果。

## 界面

顶部资源栏和调试区常驻，下面分两个页签：

- **经营**：主场景、礼物面板、模拟弹幕区。
- **研发与升级**：菜单与研发、升级面板。

切换页签只换显示内容，游戏照常运行；有菜待出餐时“经营”页签上会显示数量。

礼物面板最后一个虚线框的“测试礼物”不是作业要求的礼物，只为评审和调试方便：每点一次获得 1000 现金、红绿蓝食材各 50、铭牌碎片 20，弹幕输入 `测试礼物` 效果相同。数值在 `src/config/gifts.ts` 的 `TEST_GIFT`。

## 时间与状态

全局只有 `useGame.ts` 里的一个 `setInterval`，间隔是 1000ms ÷ 倍速，每次调用一遍 `tick()`。一个 Tick 代表 1 游戏秒。界面上的倒计时和进度条都是直接读状态里的剩余时间，CSS 过渡只负责让进度条看起来平滑。

**客人状态**

```
到店 ──排队位满──> 离开（容量流失）
  │
queuing 排队 ──超过排队耐心──> 离开（排队流失）
  │ 有空桌
  ├──菜单上没有可接受的菜──> 离开（无菜流失）
waitingStove 已点单，等灶眼（不限时）
  │ 有空灶眼
cooking 烹饪中（仙女棒可加速）
  │ 剩余时间归零
ready 待出餐 ──超过待出餐等待──> 离开，菜作废（未出餐流失）
  │ 手动出餐 / 甜甜圈自动出餐
结账：收现金、掉落材料、释放桌位
```

**一个 Tick 内的固定顺序**（`engine/tick.ts`）

1. 待出餐等待计时，超时的客人离开。放在最前，本 Tick 才做好的菜不会立刻被扣一秒。
2. 烹饪推进，做好的释放灶眼并进入待出餐。
3. 甜甜圈生效时，把待出餐的菜全部端出并结账。
4. 让队首坐进刚腾出的空桌，然后给仍在排队的客人扣耐心，耗尽的离开。
5. 按客流累加到访进度，够 1 就来一位客人；排队位满则记容量流失。
6. 落座点单。
7. 等灶的订单按点单先后占用空灶眼。
8. 礼物计时递减：魔法镜、甜甜圈、炸弹冷却。放在最后，效果在本 Tick 内完整生效。
9. 当天 Tick 数满 720 则清零今日统计。

玩家动作不经过定时器，点击后立即修改状态。出餐、甜甜圈、炸弹这三个会腾出或占用座位的动作，结束时会调用和 Tick 第 6、7 步相同的函数，所以客人不用等到下一秒才落座。

## 关键规则说明

数值都来自作业文档，位置见 `src/config/`。下面是文档没写明、实现时做出的决定。

| 规则 | 实现 |
|---|---|
| 用餐时长 | 没有用餐阶段，出餐即结账并释放桌位 |
| 材料掉落 | 文档的 6 个掉落率按表格顺序对应 6 类客人。结账时红、绿、蓝各按该概率独立判定一次，命中各掉 1 个；铭牌碎片按自己的掉落率再独立判定一次 |
| 落座后等灶眼 | 不限时，不会流失。会超时的只有排队和待出餐两个阶段 |
| 红色仙女棒 | 一根同时作用于所有烹饪中的订单，每个订单各自计数，各自 4 根封顶。每根减少的是该订单实际总时长（基础 ÷ 厨师倍率）的 20%，所以任何厨师等级下 4 根都正好保留 20%。没有烹饪中的订单，或都已吃满 4 根时不生效 |
| “2 级优先 / 3 级优先” | 菜单上有优先品级的可做菜时只从中随机；没有则点可接受范围内品级最高的。探店博主可接受 1–2 级，美食评论家可接受 1–3 级 |
| 无菜可点 | 客人照常到访和排队，落座时发现没有可接受的菜就立即离店，桌位不被占用 |
| 今日统计 | 按游戏时间算，720 Tick 为一天，暂停不走，倍速时走得快。今日客流只统计进了店的客人，不含容量流失 |
| 新菜上架 | 研发成功或药丸抽到新菜后，菜单位有空就自动上架，满了则保持“已激活”等玩家手动调整 |
| 研发条件 | 只要求饭馆等级达到菜品品级和资源足够。厨师不够时也能研发，但菜会显示厨师锁，不会被客人点到 |
| 礼物消耗 | 免费，只受各自的封顶、冷却和生效条件限制 |
| 能量药丸保底 | 记录距上次出新菜以来的抽数，第 10 抽必出新菜。“可激活的新菜”要求饭馆和厨师等级都达到该菜品级。没有这样的菜时，改发红绿蓝各 2 个，保底计数同样清零 |
| 魔法镜“最高两档客人” | 当前饭馆等级的到访池里，按表格顺序最靠后的两类客人，权重乘以 1.5 的层数次方。1 级饭馆只有两类客人，所以只有客流倍率起作用 |
| 甜甜圈 | 每个加 60 秒，上限 180 秒，已满时再送不生效。送出的瞬间会把已经在等的菜一并端出 |
| 炸弹 | 人数为 min(3 + 饭馆等级, 空桌 + 空排队位)。其中向下取整的 30% 是“到访池里、菜单上有菜可点的最高品级客人”，其余按正常到访权重抽取。来的客人先填空桌，坐不下的排队 |
| 刷新页面 | 现金、材料、等级、已激活和上架的菜、药丸保底计数、当天进度、礼物剩余时间和冷却都会保留。在场客人、订单和日志清空。没有离线收益 |

### 手工测试清单

先点调试区的“重置存档”。需要等待的步骤可以开 5 倍速。

| 编号 | 操作 | 预期 |
|---|---|---|
| T01 | 打开页面等待，不做任何操作 | 约 3 秒来第一位客人，之后每 30 秒一位。连点几次炸弹把排队区填满后继续等，日志出现“排队位已满，离开了（容量流失）”，调试区“流失：容量”增加 |
| T02 | 观察客人落座 | 桌位显示所点的菜，只会是已上架的三道 1 级菜；灶眼被占用，其余落座客人显示“等灶眼” |
| T03 | 待出餐区出现菜后点“出餐”，或在弹幕框输入 `出餐` 回车 | 该客人离开，日志显示结账金额和掉落，顶部现金和材料增加 |
| T04 | 菜做好后不出餐 | 学生 10 秒、工人 12 秒后日志显示“等不到上菜，离开了，××作废”，现金不变 |
| T05 | 用炸弹让排队区有人，不出餐使桌位一直被占 | 排队客人的耐心条走完后离开，日志显示“排队太久，离开了”，桌位数不变 |
| T06 | 攒够 60 现金、1 红、3 绿后研发香煎葱油饼 | 资源不足时按钮置灰并显示具体缺口；研发成功后状态变为“已激活”，因为菜单位 3/3 已满没有自动上架；点“上架”提示菜单位已满，先下架一道后才能上架 |
| T07 | 攒够 300 现金、2 铭牌碎片后升级饭馆 | 桌位变 4、排队位变 6、灶眼变 2、上架上限变 5、客流变 2.4；2 级菜从“未解锁”变为“可研发”；上班族和博主开始到访 |
| T08 | 饭馆 2 级后先研发一道 2 级菜，再用 200 现金升级厨师 | 升级前该菜带“厨师 2 级”锁，没有客人点它；升级后锁消失，菜单里各菜的烹饪秒数变为原来的 1/1.25 |
| T09 | 有菜在烹饪时连点仙女棒；灶眼全空时再点 | 灶眼上的剩余时间每次减少总时长的 20%，显示 🪄×N，第 5 次提示已吃满 4 根；空灶时提示没有烹饪中的订单 |
| T10 | 连点能量药丸 | 日志逐条显示奖励；保底进度到 10 时必出新菜并显示“（保底）”；1 级饭馆抽到一次新菜后再触发保底，会显示转为红绿蓝各 2 |
